# Specification — Compiler profile, compilation and evaluation

**Status:** Proposed. **Owner:** existing `pipeline-scripting-kotlin24` adapter and scripting ports. **Decisions:** ADR-EVO-011/014.

## 1. Existing authority, explicit implementation phases

`SCRIPTING_COMPILER_SPEC.md` already defines `PipelineScriptEngine.compile/evaluate` and `PipelineCompiler`. The baseline implementation exposes `ScriptingHost.compile` with a compile-and-evaluate contract, `ScriptCompilationResult` and `CompiledScriptedEntryPoint`. Inventory/reconcile consumers before adding a public type. No third engine, Gradle runtime dependency or duplicate dispatcher.

Separate phases internally first and preserve the public compatibility adapter. Any port migration requires the existing ABI/consumer/corpus gate. Experimental Kotlin types stay inside the adapter. Retain `ScriptedArtifactIdentity` fields used by replay; map compilation identity to that authority without casually replacing replay fingerprints.

## 2. Phase contract — GR-001

| Phase | Input/result | Owner | Allowed effects |
| --- | --- | --- | --- |
| Resolve | References to complete dependency graph | Existing resolver ports/application | Declared transport and owned cache I/O |
| Admit/freeze | Admitted immutable bytes/composition snapshot | Admission/current SDK composition | Static inspection; contributors initialize only after admission |
| Compile | Source/profile/plan to compiled representation | Kotlin adapter/compiler | Compiler work/diagnostics/owned writes; script body not evaluated |
| Load | Valid representation to compatible classes/metadata | Kotlin adapter | Controlled loading and compatibility checks |
| Evaluate | Loaded code plus fresh invocation context | Existing evaluation path | DSL construction/evaluation under current contract |
| Execute | Declarative IR or scripted entry point to outcome | Existing durable/registry spine | Registered operations with current admission/replay/recovery |

GR-002: compilation does not run the script body. GR-003: hits still evaluate with a fresh receiver/context wherever evaluation is part of the frontend. Compilation events never imply StepStarted.

Declarative evaluation builds IR. Scripted pipelines retain dynamic control flow and their entry-point execution contract; not all scripted operations must become a static graph before execution.

## 3. Dependency preparation

Gradle's staged plugin processing motivates preparing dependencies before body compilation. PipelineK uses existing YAML/configuration, manifest/admission and the typed plan. Keep options, agents and params on their established configuration surfaces. Do not add `plugins {}` or `@file:DependsOn` as another dependency authority.

Freeze plugin/library/transitive identities first. Generate approved façades from those authorities and include generated bytes/schema revision in identity. Pass an explicit compiler classpath, coherent with evaluation/runtime identities. Exclude compiler implementation internals from exported script API.

Classloader scoping controls visibility and JVM type identity; it is not an OS sandbox and cannot prove arbitrary Kotlin effect-free.

## 4. Effective compiler profile — GR-006

One adapter-owned profile supplies actual configuration and identity material: distribution compiler/runtime artifacts, language/API, JVM target, compilation JDK/API roots, template/imports, lowering/façade revisions and options. Application supplies admitted dependencies. CLI/LSP/MCP do not invent competing defaults.

Read versions from actual distribution/build metadata and verify artifacts; do not add another hard-coded Kotlin string. Every compilation-affecting dimension changes identity.

The canonical baseline is Kotlin 2.4.10, JVM target 21 and JDK 21; JDK 25 is the existing additional validation target. A JDK 24+ probe exercises Unsafe deny mode; this probe alone does not certify every runtime feature on that JDK. Upgrades require the compatibility corpus.

## 5. JAR reader/JVM policy — GR-007

Select the standard JAR reader explicitly in productive host and mapper: scripting option `-Xuse-fast-jar-file-system=false` and the corresponding mapper configuration key. Keep the return-value checker and real DSL/diagnostic gates.

Installed regression: fresh JDK 24+ JVM with `--sun-misc-unsafe-memory-access=deny`; valid compile/mapping succeeds, real type error fails with location, source warning remains. A mutation removing reader policy must kill the positive probe when the original dependency is present.

Do not make `--sun-misc-unsafe-memory-access=allow` the default correction. Gradle 9.8 permits Unsafe in its daemon for bundled runtime dependencies; that is warning suppression, not elimination. Here avoid the specific compiler operation and prove deny compatibility. A Kotlin patch upgrade is not assumed to fix it. Measure reader cost before further optimization.

## 6. Evaluation and validate — GR-008

Preserve declarative construction failures, scripted return semantics and evaluated output of the current `compile` compatibility method. A cache may not substitute an uninitialized class handle for that output.

`pipelinek validate` currently compiles and evaluates DSL construction. Preserve/document its actual contract; it is not automatically an effect-free arbitrary-Kotlin checker. Top-level Kotlin may perform I/O independently of registered Steps. Pure `step --plan` accepts typed invocation data and calls preparation, not arbitrary script evaluation. A restricted/isolated compile-only validate mode needs an explicit compatibility decision.

Characterize pure expressions, null/Unit/no-value, construction failures, returnStdout/returnStatus, discarded carriers and both frontends. Assert observed severity/behaviour, not a promised compile error inferred from an inaccurate comment.

## 7. Diagnostics — GR-009

Preserve code/message/raw severity/location and project phase/origin through the existing read model. Compile diagnostics may accompany the artifact; evaluation/runtime diagnostics are fresh. Hits remap current locations without changing severity.

Human verbosity may control configuration-notice presentation, retaining structured diagnostics/evidence. No blanket stderr, INFO, warning or synthetic-location filter. Kotlin's reader INFO does not become a failure or hide source warnings. New observability metadata/events follow current SDK/schema gates and never change execution semantics.

## 8. Acceptance

UAT-054/055/062/070/071/072/073, AAT-015/021/022/026 and the existing source-map/DSL/entry-point corpus. Compiler, evaluation and handler invocation counters are distinct test seams; real compilation is required. Phase/profile correctness is mandatory even when persistence/session reuse is NO-GO.
