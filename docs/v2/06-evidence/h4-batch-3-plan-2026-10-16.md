**Migration paths for the 5 V2 support files in V2_GRADLE:**

1. `CorpusSnapshotDiffer.kt` (PK-RET-0041) — 1 dependent
   (`CorpusSnapshotDifferTest.kt`). Migration path: retire
   `CorpusSnapshotDifferTest.kt` (in `TRIAGE_CONSOLIDATION`

   contract test for the snapshot/diff fingerprint). Once the
   test is retired, the support file loses its last dependent
   and can be retired.
2. `CorpusNormalizer.kt` (PK-RET-0039) — 3 dependents, all
   V2 tests. Migration path: same as above for each test
   (3 separate certifier verdicts, or refactor each test to
   not need the normalizer).
3. `Subprocess.kt` (PK-RET-0066) — 5 production dependents.
   Migration path: this is the highest-impact entry. The 5
   production files in `v2/pipeline-application/src/main/`
   reach `Subprocess.kt` despite it being in `src/test/` (the
   test-support class is reachable from production code
   because Kotlin's `internal` modifier is the only boundary
   and the production code declares the dependency).
   Migration requires either:
   a. Move `Subprocess.kt` to `v2/pipeline-application/src/main/`
      (a refactor, not a retirement; the file stays).
   b. Rewrite the 5 production files to not depend on
      `Subprocess.kt` (a refactor; the file goes).
   c. Mark `Subprocess.kt` as `internal` and rewrite the
      production callers to use a public seam.
   Any of these is multi-step; the H4 mandate's STOP rule
   does not forbid them because no test is being deleted.
4. `SubprocessFixtureProgram.kt` (PK-RET-0067) — 1 dependent
   (`OwnedSubprocessRunTest.kt`). Migration path: same as
   `CorpusSnapshotDiffer.kt` — retire the test, then the
   support file.
5. `SubprocessOutcome.kt` (PK-RET-0069) — 2 dependents
   (`Subprocess.kt` itself and `SubprocessHarnessTest.kt`).
   Migration path: dependent on #3 (Subprocess.kt retirement)
   and a separate decision for `SubprocessHarnessTest.kt`.
