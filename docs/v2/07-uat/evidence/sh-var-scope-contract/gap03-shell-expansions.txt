CONTRACT BEHAVIOUR LOCKED BY THIS GAP03 TEST
================================================================

The test pins byte-level behaviour for the three authorised shell
expansion shapes referenced by Gap #3 in spec.md. Each sub-case
constructs source with `String` concatenation so the bytes the test
passes to the production pipeline are exactly the bytes a user
would type into a `.pipeline.kts` file.

Verbatim assertions:

gap03a — braced default expansion \${OPTIONAL:-fallback}
  envVars: {}      (withEnv is NOT a source of envVars by G1)
  escaped: byte-identical to source
  contract: \${VAR:-default} survives the escoper so bash applies
            its default-expansion semantics when VAR is empty.

gap03b — command substitution \$(hostname)
  envVars: {}
  escaped: byte-identical to source; contains literal \$(hostname)
  contract: \$(...) survives the escoper so bash performs command
            substitution at run time.

gap03c — glob-strip \${PATH_STR##*/}
  envVars: {}
  escaped: byte-identical to source; contains \${PATH_STR##*/};
           does NOT contain \${'$'} (no trap injection)
  contract: the glob-strip suffix form reaches bash verbatim;
            the escoper does not inject a trap-form footprint.

INTERESTING RED — captured for the record (rule 21 compliance):

  The first attempt at gap03c concatenated `bsl()+"*/"` before the
  closing brace, producing `\${PATH_STR##\*/}` (with an extra
  backslash). The assert `escaped.contains("\${PATH_STR##*/}")`
  failed because the byte stream had a backslash where the
  contract says none should be. The test was rewritten to
  `"PATH_STR##*/" + rc()` (no bsl() before `*`), and went
  green on the next run.

  This is exactly the failure mode that Guard G2 ("bytes, not
  aspect") catches — a source that LOOKS like it has the right
  pattern (##*/ is the glob-strip) but the actual byte stream
  carries a stray escape byte that bash would never read as a
  glob.

CONCLUSION:

  - The three authorised shell expansion forms survive the
    production escoper pipeline when envVars is empty.
  - The trap form (\${'\$'}) is NEVER injected by the escoper
    when envVars is empty (asserted in 03c, same property locked
    by Gap #2 02c).
  - The bytes that flow forward to core.sh carry the literal
    shell-expansion forms the user wrote.
